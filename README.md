# 字幕固定与去重叠（Cue Lock）

纪录片补录工具单页：锁定少数字幕起点、给每条字幕设置可选切点窗口，并消除
全部相邻重叠；顶层可切换到 **现场旁白采集** 录音台。

## 求解模型

变量为每条字幕的整数起点 `x[i]`，约束：

- `0 ≤ x[i] ≤ 86_400_000`（全天毫秒）
- `x[i+1] ≥ x[i] + duration[i]`（相邻不重叠）
- `earliest[i] ≤ x[i] ≤ latest[i]`（可选闭区间；旧三字段文件视为全天窗口）
- 固定点 `x[cueIndex] = start` 精确命中

目标是最小化相对已采纳稿 `base[i]` 的绝对位移总和
`Σ |x[i] − base[i]|`；多解时取按 cue 顺序字典序最小的整数向量。求解器直接
在完整窗口约束上做保序回归，不会先求无窗口结果再逐项裁剪。

令前缀时长 `P[i] = Σ_{k<i} duration[k]`，`y[i] = x[i] − P[i]`、
`b[i] = base[i] − P[i]`，问题化为**带逐点上下界的 L1 保序回归**：
`y` 单调不降，同时 `y[i]` 必须位于自身窗口、全天边界和固定点变换后的整数
区间中。

- PAVA 合并违例块；块值取原始观测的**下加权中位数**，再投影到块内窗口
  交集，既保证最优也给出字典序最小解；
- 固定点是下界等于上界的精确观测；块内双半区用左倾堆（lower 最大堆 /
  upper 最小堆）维护，整体 **O(n log n)**，20 000 项求解耗时远低于 2 秒；
- 一次前向前缀时长包络配合后向上界包络判定可行性，并报告最早冲突 cue。

### 不可行诊断

结果稳定区分两类需要不同处理的冲突：

1. `PIN_OUTSIDE_WINDOW`：固定点自身不在 cue 的 `[earliest, latest]` 内；
   返回 cue、固定起点以及允许的上下界。
2. `WINDOW_CHAIN`：固定点虽在自身窗口中，但前序时长、全天边界或前序窗口链
   无法传递到该点；返回最早冲突 cue、所需起点与允许上界。全天装不下也归一
   到这一类链冲突。

## 页面流程

1. 导入 JSON：根对象仅含 `cues`，1–20000 项。每项必须含整数
   `start`（0–86400000 且严格递增）、`duration`（1–60000）、`text`
   （1–200 字符）；可独立添加整数 `earliest`、`latest`（闭区间）。越界、
   反序、缺失必需字段或额外字段都会拒绝整份导入；旧三字段文件继续按全天
   窗口处理。
2. 行内可编辑固定起点、`earliest`、`latest`。清空可选边界表示恢复默认
   （0 或 86400000）；非整数、越界或反序修改当场拒绝且不替换原值。
3. 预览：显示新起点、逐行位移和当前窗口；约束不可行时显示分类诊断并清空
   预览。此时可在提示旁**生成最大保留修复**：
   - 修复分析始终基于生成时的 cues/pins 窗口快照；
   - 若窗口本身（没有任何固定点时）不可行，解除固定点无法恢复，因此不生成
     方案，并返回窗口链的最早冲突 cue、所需起点与允许上界；
   - 否则先剔除自身窗口外或被全局前后缀包络判定为不可共同保留的固定点，
     再在剩余固定点中求可共同满足（变换值非降）的最大基数集合（LNDS）；
     最大集合并列时比较完整 cueIndex 升序解除列表，取字典序最小者；
   - 预览只显示保留数与完整解除清单；分析是纯函数，不触碰 pins、基线、
     窗口或当前错误。
4. 采纳：预览结果成为下一轮基线；固定点和每条 cue 的窗口保留，便于迭代。
5. JSON 下载/导入保留显式 `earliest/latest`；旧三字段输入仍输出三字段。
6. 修复方案携带生成时的工作稿、基线、固定点与窗口**修订身份**；应用时四者
   复核一致才一次性替换 pin Map 并重新求解，否则动作提示**已过期**且不产生
   任何部分修改。任何导入、采纳、固定点增删改或窗口修改都立即作废旧方案。

## 现场旁白采集

顶层「现场旁白采集」与字幕编辑互斥切换；录音台是完全独立的会话，**不读取
任何字幕数据**。切回字幕页即卸载录音台并幂等释放全部资源。

状态机：`请求授权 → 待录 → 录制 → 封装 → 复听`，复听可播放成品或
「废弃重来」（重新授权并开启递增会话号的新会话）。

- 权限与录制器**只在点击「启用麦克风」后**创建；初次渲染与 StrictMode
  重挂载（构造→销毁→再构造）不请求权限、不产生并行录制器；
- 所有媒体调用走可注入适配器 `NarrationMediaAdapter`（浏览器实现外可在
  Vitest 中注入伪适配器）；启用时先协商 `MediaRecorder` 支持的 MIME；
- 递增会话号绑定录制器、音频块与对象 URL；只有当前会话同时收到最终
  非空 `dataavailable` 与 `stop` 后才用非空块生成 take，迟到事件无法
  覆盖新 take；
- `AnalyserNode` 采样仅驱动输入电平条；时长取 `performance.now()`
  单调时钟差，后台限频只暂停刷新，不截断录音、不改变最终字节；
- 不支持录音、拒绝授权、无设备、音轨中断、启动/编码错误、封装失败、空
  数据均进入可恢复错误（重试 / 返回）；停止、切页与卸载幂等关闭音轨、
  音频图并撤销对象 URL。

## 开发

```bash
npm ci
npm run dev       # 开发服务器
npm run build     # tsc 类型检查 + Vite 构建
npm test          # Vitest（穷举核对 + 性能）
npm run verify    # build && vitest run（一次性验收命令）
```

测试用短时间轴独立穷举全部整数可行起点与固定点子集，与求解器核对：

- 可行性、冲突分类、最早冲突 cue、所需起点、允许上界；
- 最优绝对位移成本与完整字典序起点向量；
- 旧三字段文件、显式单侧/双侧窗口、额外字段和反序窗口的导入导出；
- 最大保留修复的强制解除清单、最大保留集合、平局裁决和窗口不可行；
- 修改窗口后旧修复方案过期，应用无副作用；
- 20 000 项/固定点对抗模式的 O(n log n) / O(k log k) 2 秒时限。

## Docker Compose

```bash
WEB_PORT=8080 docker compose up web --build      # 发布页面
docker compose --profile verify run --rm verify  # 一次性验收服务
```

`WEB_PORT` 默认 8080。
